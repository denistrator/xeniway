# Internationalization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Localize the React user interface into English, Russian, and Ukrainian with lazy-loaded RU/UK resources and a browser-local language preference.

**Architecture:** `i18next` is the language source of truth and `react-i18next` exposes it to components. English resources are part of the initial application bundle; Russian and Ukrainian dictionaries are dynamically imported before initial React render or when the user selects a locale. API/database values remain canonical; the browser maps API error codes and formats dates using the active locale.

**Tech Stack:** Bun workspaces, React, Vite, TypeScript, Redux Toolkit, TanStack Query, i18next, react-i18next, Vitest, Playwright.

## Global Constraints

- Support exactly `en`, `ru`, and `uk`; use `UK` only as the compact visual label for Ukrainian.
- English is the fallback locale and only English is bundled initially; RU and UK are loaded via dynamic imports.
- Persist the explicit browser choice only under a dedicated local-storage key; do not add a database field, API parameter, or user preference mutation.
- Translate all current frontend copy and accessible labels, but never automatically translate candidate-entered application data.
- Preserve routes, API contract fields, status values, form IDs/names/autocomplete, keyboard behavior, and theme behavior.
- Keep API/server messages, SMTP mail, seed data, and documentation localization out of scope.
- Use `Intl.DateTimeFormat(activeLocale, options)` for display dates and keep stored dates as ISO values.
- Run `bun run format` after edits and `bun run lint` before each commit.

- [ ] **Step 5: Implement locale resolution, dynamic loading, and initialization**

Create `i18n.ts` with a single explicit loader for each supported locale. Keep English static; load RU and UK only with dynamic imports.

```ts
import i18n from "i18next";
import { initReactI18next } from "react-i18next";
import { en, type TranslationDictionary } from "./locales/en";

export const supportedLocales = ["en", "ru", "uk"] as const;
export type SupportedLocale = (typeof supportedLocales)[number];
export const languageStorageKey = "xeniway-language";

const loaders: Record<Exclude<SupportedLocale, "en">, () => Promise<{ default: TranslationDictionary }>> = {
  ru: () => import("./locales/ru"),
  uk: () => import("./locales/uk"),
};

export function resolveLocale(stored: string | null, browserLanguage?: string): SupportedLocale {
  if (supportedLocales.includes(stored as SupportedLocale)) return stored as SupportedLocale;
  const base = browserLanguage?.toLowerCase().split("-")[0];
  return supportedLocales.includes(base as SupportedLocale) ? (base as SupportedLocale) : "en";
}

async function ensureLocaleResources(locale: SupportedLocale) {
  if (i18n.hasResourceBundle(locale, "translation")) return;
  if (locale === "en") return;
  const module = await loaders[locale]();
  i18n.addResourceBundle(locale, "translation", module.default, true, true);
}

export async function changeLocale(locale: SupportedLocale) {
  await ensureLocaleResources(locale);
  await i18n.changeLanguage(locale);
  window.localStorage.setItem(languageStorageKey, locale);
}

export async function initializeI18n() {
  const locale = resolveLocale(window.localStorage.getItem(languageStorageKey), window.navigator.language);
  await i18n.use(initReactI18next).init({
    resources: { en: { translation: en } },
    lng: "en",
    fallbackLng: "en",
    supportedLngs: supportedLocales,
    interpolation: { escapeValue: false },
    react: { useSuspense: false },
  });
  if (locale !== "en") await changeLocale(locale);
}

export { i18n };
```

Export default dictionaries from `ru.ts` and `uk.ts` so the loader contract is valid.
